SQL Warehouse Academy

A database is a giant warehouse. Tables are shelves, rows are boxes, columns are labels on each box. SQL is the language you use to talk to the warehouse clerk — you never walk the aisles yourself; you write a precise request slip and the clerk fetches exactly what you asked for.

Anatomy of a Query

📋 Metaphor: a SELECT statement is a request slip handed to the clerk. Each clause is one line on the slip: which shelf, which boxes, how to sort them, how many to bring back.
SELECT  name, price          -- WHAT labels to copy off each box
FROM    products             -- WHICH shelf (table)
WHERE   price > 100          -- FILTER: only boxes matching this test
ORDER BY price DESC         -- SORT the boxes before delivery
LIMIT   5;                   -- bring at most 5 boxes
Clerk's secret: the clerk does NOT read the slip top-to-bottom. Real execution order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. That's why you can't use a SELECT alias inside WHERE — the clerk hasn't written the label yet when filtering.

GROUP BY — Sorting Boxes into Bins


🗂️ Metaphor: GROUP BY = the clerk drags all boxes into bins by label (one bin per category), then reports one summary line per bin — count, average, total. You never see individual boxes again, only bin summaries. HAVING = throwing away whole bins that fail a test.

Indexes — The Card Catalog


🗃️ Metaphor: without an index, the clerk walks every aisle to find your box (full table scan). An index is a card catalog: sorted cards saying exactly which aisle each box lives in. Lookup becomes a few card flips (binary search, O(log n)) instead of a full walk (O(n)). Cost: every new box also needs a new card — writes get slightly slower.



  

    
    
  

  
  






Modern SQL (What's Current in 2026)



  
CTEs — WITH
Metaphor: a scratch pad. The clerk prepares a temporary pile on a side desk, names it, then queries the pile. Replaces nested subqueries; makes queries readable.
WITH big_spenders AS (
  SELECT customer_id, SUM(total) t
  FROM orders GROUP BY customer_id)
SELECT * FROM big_spenders WHERE t > 1000;

  
Window functions
Metaphor: each box gets a sticky note about its neighbors — rank within its bin, running total — without collapsing bins like GROUP BY does. The #1 interview topic for data roles.
SELECT name, price,
  RANK() OVER (PARTITION BY category
               ORDER BY price DESC) r
FROM products;

  
SQL:2023 standard
Latest standard adds native JSON type + dot notation (data.address.city) and property-graph queries (GRAPH_TABLE) — query relationships like a graph DB, inside SQL.

  
Ecosystem 2026
PostgreSQL = default choice (most-loved DB, Stack Overflow surveys). SQLite = in your pocket (every phone). DuckDB = hot analytics engine, runs SQL on CSV/Parquet files locally. AI writes SQL now — but you must read it to trust it. SQL is ~50 years old and still top-5 most-used languages.
